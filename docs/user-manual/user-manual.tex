\section{Overview}
The \textbf{Chess Club Tournament \& Rating Manager} is a desktop application for managing chess-club tournaments and Elo ratings. It supports player creation, tournament and round creation, registration, game recording, automatic Elo updates, rating history, and standings with Buchholz tiebreaks.

The main window contains six tabs: \textbf{Players}, \textbf{Standings}, \textbf{Rating History}, \textbf{Record Game}, \textbf{Register Player}, and \textbf{Create Tournament}.

\section{Setup and Startup}
\subsection{Requirements}
Install Docker with Docker Compose, Python 3, and Git if the repository must be cloned. Create \texttt{.env} from \texttt{.env.example} in the repository root.

\subsection{Start the backend}
PostgreSQL and FastAPI run together as Docker Compose services:
\begin{verbatim}
docker compose up -d --build
\end{verbatim}
Check the API at:
\begin{verbatim}
http://127.0.0.1:8000/health
\end{verbatim}
A working backend returns \texttt{\{"status":"ok"\}}.

\subsection{Start the frontend}
Linux/macOS:
\begin{verbatim}
PYTHONPATH="$PWD/frontend" python3 -m chess_club_fe.main
\end{verbatim}
Windows PowerShell:
\begin{verbatim}
$env:PYTHONPATH="$PWD\frontend"
py -m chess_club_fe.main
\end{verbatim}
At startup, a connection dialog asks for the API URL and \texttt{X-API-Key}. For local use, enter \texttt{http://127.0.0.1:8000} and the \texttt{API\_KEY} value from \texttt{.env}. The dialog validates the connection before the main window opens.

On Debian/Ubuntu, \texttt{./scripts/run-local.sh} starts the containerized backend and source frontend. If the Debian package is installed, launch it with \texttt{chess-club-manager}; the backend containers must already be running.

\section{Using the Application}
\subsection{Players}
Open \textbf{Players} to view existing players or click \textbf{Add Player}. Enter a name, optional birth year, and initial Elo. Creating a player also creates the first rating-history entry.

\subsection{Create Tournament}
Open \textbf{Create Tournament}, enter a name, start date in \texttt{YYYY-MM-DD} format, and number of rounds. The application creates all round records automatically and shows their IDs.

\subsection{Register Player}
Choose a player and tournament, optionally enter a seed, and click \textbf{Register}. Both players must be registered before recording a game; duplicate registration is rejected.

\subsection{Record Game}
Enter the round ID, White player, Black player, ECO code, and result. Valid results are \texttt{1-0}, \texttt{0-1}, and \texttt{1/2-1/2}. A successful game updates both Elo ratings and creates two new rating-history entries.

\subsection{Standings and Rating History}
\textbf{Standings} shows points, Buchholz, wins, draws, losses, and games played. \textbf{Rating History} shows all Elo-history rows or filters them by player.

\section{Troubleshooting and Scope}
If the API cannot be reached, run \texttt{docker compose ps} and check the health endpoint. If the connection dialog rejects the key, use the exact \texttt{API\_KEY} value from \texttt{.env}. If Docker fails, ensure the Docker service is running and retry \texttt{docker compose up -d --build}.

The delivered version intentionally does not include automatic pairing generation, edit/delete GUI operations, automatic tournament closing, user accounts, or detailed opening analytics.
